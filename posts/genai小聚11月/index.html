「MCP 還有未來嗎？會不會過幾年，我們就像聊 WAP 一樣聊它？」

（如果你不知道 WAP 是什麼，沒關係，這個例子已經完成它的工作了 😂）

11/11 去 Generative AI 小聚分享〈MCP 只是開始：從工具連接到多 Agent 的共享記憶〉，開頭我就先丟了這個自己其實也想了很久的問題 🙌

之前寫〈淺談 MCP 產品化〉那幾篇文章的時候，我心裡也還在觀望 MCP 這個 protocol 到底會不會繼續走下去，到底會變成下一個 USB-C，還是下一個 3D 電視？因為很多新技術剛出來大家一窩蜂做 demo、包工具，過一陣子發現 production 不好用，最後就變成 side project 的墳場。

不過這半年一路看下來，我覺得它真的有慢慢從單純的「Connector」長成「Agent Infrastructure」的樣子。

以前幫 AI 串工具，左邊接一條、右邊接一條，大家都在當接線生；有了共同的標準雖然省事很多，但工具越裝越多，tool definitions 跟回傳資料又開始把 context 塞爆。

這次分享前半段，我也整理了最近大家為了解決這類問題、在 MCP 上玩出來的三種常見做法：

① Tool Search：需要什麼工具，再去找。

不用一開始就把整本工具目錄塞進 AI 腦袋，讓 Agent 先搜尋這次需要的工具，再載入對應的工具定義。Anthropic 的官方範例就展示了約 85% 的工具相關 context 減量，先幫 AI 留一點空間做正事。

② Gateway／Router：幫一堆服務設一個總機。

把不同 MCP Server 的入口集中起來，由這一層負責把請求送到對的地方，也能集中處理授權、存取控管與使用紀錄。這裡主要解決的是服務怎麼接、誰可以用、怎麼管理，單純多放一個 Gateway，context 不會自己變小。

③ 後端 Code Execution：讓程式先把資料處理好，再交回結果。

讓 Agent 寫程式，在後端把多個操作串起來、篩選和整理資料，再把這次需要的結果交回來。像 Cloudflare 的 Server-side Code Mode，對外只有 search()、execute() 兩個工具，後面卻能存取 2,500 多個 API endpoints，起始工具定義只需要約 1,000 tokens。前台看起來很精簡，後台其實忙得要命。

另外，今年 7/28 的官方規格更新，也把協定核心改成 stateless，讓請求更容易分派到不同的 server instance，往更容易擴展、部署的方向走。這跟前面把資料處理留在後端，是不同層次的改進。

越往裡面做，越確定接上 MCP 之後還有很多東西可以玩，而我自己的切入點則是往「記憶」這一塊繼續挖下去。

會往這塊挖，最根本的原因其實是我們在做 Agent 的過程中慢慢發現，記憶幾乎直接決定了 Agent 能理解你多少、能有多可控，也決定了它最後能不能真的把一整段 end-to-end 的工作扛起來，而不是每次都只能幫你做一小段。

放到日常工作裡看，最有感的就是每天一直在當人工搬運工 🫠 現在手邊同時開好幾個 AI 視窗已經是常態，但常常跟 Claude 討論好一整套背景，轉頭換另一個 coding agent 接手時，全部又要重新解釋一次。現在做到哪裡、當初為什麼選這個方案、哪些方法已經試過失敗了，每天都在無限 Ctrl+C 跟 Ctrl+V，工具買了一大堆，結果我自己變成了它們的物流中心。

所以這次分享的後半段，我主要在聊自己一路踩坑下來，嘗試透過 MCP 讓「共享記憶」真的用得上時，撞上的幾個具體問題：

  • 寫入：對話這麼多，哪些事情才值得記下來？隨口討論的點子跟已經拍板的決定要怎麼分開？
  • 維護：方向轉彎或決策改了，舊記憶怎麼更新？萬一兩份紀錄互相矛盾，AI 下次該聽哪一份的？
  • 取用：下一個 AI 接手時，怎麼剛好拿到這次工作需要的脈絡，而不是每次都重新讀完整座資料山？

投影片裡我用了一個很生活化的例子：「我平常愛吃辣，但這週不吃辣。」

原本的偏好還在，只是這週多了一個限制。等另一個 Agent 幫忙推薦午餐時，它就要知道這次先找不辣的。要記得的除了內容，還有這件事在什麼時間、什麼情況下適用。

這件事如果只是一個人用還算單純，自己的 second brain 自己說了算；但當我們想把記憶從個人延伸到團隊的 company brain，馬上又會多出誰能看、誰能改，以及不同人跟 Agent 意見衝突時誰說了才算數的麻煩。

回頭看從最早期土法煉鋼用 Markdown、GitHub 同步檔案，一路試到現在透過 MCP 來接記憶層，其實想解的一直都是同一件事，就是那些已經花時間討論過、試錯過的經驗，能不能在下一次工作時直接派上用場。這次邊整理投影片也邊幫自己重新復盤了一次，發現把東西記下來真的只是起點，後面怎麼更新、除錯跟管好權限，讓下一個人或下一個 AI 真的敢放心接手，才是更花功夫的地方。

我自己現在如果要測試一套記憶好不好用，最直接的做法就是先挑一個手邊的專案，把背景、重要決策跟理由、還有待辦事項留好，接著直接換一個新對話或換另一個 AI，看它能不能不用我多解釋就順順接著往下做。光是試這一次交接，常常就會發現一堆平常其實都靠自己腦袋在硬補的脈絡 😅

很感謝 Generative AI 小聚主辦團隊的邀請與安排，也謝謝當天來現場聽分享、一起交流的大家！這篇也附上幾張當天的投影片，如果你平常也是同時開好幾個 AI 視窗在切換，或是正在研究記憶怎麼跨工具接起來，歡迎一起交流，希望哪天 AI 們越來越會自己交接，讓我這個物流中心可以早點下班 XD
