昨天跟朋友聊到李開復的《AI 未來已來》，聊著聊著冒出不少有趣的想法。這本書我今年 9 月就看完了，當時讀完覺得收穫很大，先前寫另一篇長文聊「為什麼 AI Coding 最早爆發」的時候，就曾經借過書裡「因為 Code 天生可以被驗證」那個觀點。

昨天跟大家聊完，我回頭翻了一下當時在電子書裡劃的三百多條重點，發現書裡後半段在談「企業 AI 決策中樞」跟「老闆 AI」的章節，跟我們從今年 6 月開始做 Cairn 的 Agent Memory、一路延伸到最近在研究的 Company Brain（公司大腦）高度重疊。現在市面上談 Company Brain 的人很多，但大家對於「CEO 的大腦」該長什麼樣子，討論反而還沒有很多。趁著昨天聊開了，想再寫一篇，把書裡這塊很有啟發的幾個觀點，連同我們自己這小半年做下來的體會分享給大家。

讀幾份文件跟讀懂一家公司，完全是兩回事

很多公司在導入 AI 的時候，第一個念頭就是把內部規章跟歷史文件全部丟進向量資料庫，做一個讓大家問問題的知識庫。但書裡直接點出一個很扎心的現象，員工自己私下用豆包或 DeepSeek 都覺得挺好用的，為什麼公司一旦正式部署這類知識庫工具，往往過一陣子就沒動靜了？

作者在書裡用了一個很傳神的比喻，他說傳統 RAG 做的事情，就像先把資料全部撕碎，等你提問的時候，再去一地碎紙裡撈出幾片「看起來字面相關」的內容拼成答案。這種做法只能幫你從某份文件裡摘出一句話，卻沒辦法幫你在不同系統、不同時間跟不同業務對象之間建立連結，因為讀幾份文件跟「讀懂一家公司」根本是兩碼子事。

這跟我們自己在做 Moss（我們內部的 Manager Agent）時撞到的牆一模一樣。當時我想讓 Moss 幫我管理其他 Agent 的工作分配，結果跑起來才發現，最大的瓶頸根本不在模型的推理能力，在於它不知道公司現在整體的狀況是什麼。單純餵給它一堆靜態文件，它就像一個剛入職第一天、手裡卻沒有公司地圖的新人，再聰明也只能一路碰壁。

那一個真正能當作「公司大腦」的決策中樞需要什麼？書裡把它拆成四塊拼圖，這個拆法我覺得非常清楚：

  • 會思考的大腦，也就是底層的 AI 模型
  • 靜態的業務地圖，書裡稱為本體（Ontology），用來把客戶、合約、專案、營收跟回款之間的關係固定下來，而且新一代的做法是讓最懂業務的人直接用自然語言把這張地圖畫出來，不用再全靠工程師手刻規則
  • 即時的導航系統，也就是「企業即時上下文」，負責把地圖上每天發生的交易、狀態變更、審批進度跟會議討論按時間順序記下來，讓系統知道公司此刻處在什麼狀態
  • 持續進化的作業系統，核心是「技能化（Skillification）」，當專家帶著多 Agent 完成一次複雜任務後，系統會自動回溯過程，把有效步驟跟適用邊界提煉成一份可以反覆調用的技能文件

看到書裡講「技能化」那一段，幾乎就跟我們在 Agent Memory 系列聊過的記憶演化接在了一起。一段經驗剛發生的時候只是一次性的案例（Case），累積幾次之後會被整理成做事的攻略（Strategy），最後被驗證過無數次，就會沉澱成可以直接呼叫的技能（Skill）。當一家公司能把這四塊拼圖轉起來，組織記憶才會跟著業務一起長大，不會永遠只是一堆沒人更新的死文件。

把視角拉到 CEO 大腦：穿透資訊濾鏡，讓判斷力可以複利

前陣子我去 AppWorks 跟幾位 Founder 聊 Company Brain，發現大家在討論公司大腦的時候，大多是從底下往上看，想的是怎麼幫第一線的業務、產品或客服省掉找資料跟重複傳話的時間。這本書很特別的地方，在於它直接從金字塔最頂端往下切，帶大家看如果這顆大腦是給 CEO 用的，它長得會有什麼不一樣。

書裡分享了他們團隊花 6 個月打磨 19 個 Agent、整合成一套「老闆 AI」的經驗。為什麼老闆需要自己的一套 AI？因為你在公司裡坐得越高，就越容易離真相越遠。壞消息往上傳的過程往往會被一層一層美化成中性甚至好消息，開重大會議的時候，大家為了不得罪人，也很容易維持一種表面上的和諧。所以書裡的「老闆 AI」花了很多力氣在幫 CEO 穿透層級，在資訊被層層包裝之前，先從 CRM 底層、郵件、會議錄音語氣跟文件修改紀錄裡，留下一份沒加濾鏡的底稿。除此之外，它還配了一個戰略推理沙盤，讓 CEO 在資訊不全、準備拍板之前，可以先換不同的假設自我對弈 10 遍；等事情做完之後還能拿來復盤，避免人類的記憶自我美化，最後變成「成功了人人爭功、失敗了原因成謎」。

除了幫老闆看清現況，書裡還提到了另一個讓我很有啟發的概念，叫做「讓決策品質可以複利化」。作者在講 CTO 與 CAIO 的 AI 時，設計了一張「知識風險地圖」，用來盤點公司裡哪些關鍵技術跟業務 know-how 還只鎖在某個老工程師或高管的腦袋裡，還沒真正沉澱進系統。過去一次好的判斷只出現在某個資深主管的腦子裡，人離開了就得重來；但如果能把這些決策邏輯、客戶認知跟業務脈絡記錄進系統，每一次好的判斷就能變成下一次決策的起點，甚至連未來的接班人都能繼承公司過去幾十年的判斷邏輯。

我們這小半年在做 Cairn、研究 Agent Memory 的時候，也一直在處理幾乎一樣的事。記憶如果只記下「最後決定做 B」這個結論，留下來的就只是冷冰冰的歷史紀錄；真正有價值的，是把「當初為什麼淘汰 A、看重哪個條件、在什麼前提下才這樣選」一起記下來，再把後來的結果（Feedback）接回去。唯有這樣，組織的判斷力才真的能像書裡說的一樣開始複利累積。不過，當我們順著書裡這張藍圖真的動手去寫系統時，馬上就會在日常資料裡碰到一個很現實的工程難題。

順著藍圖往下做：當所有脈絡都收進來，怎麼知道哪句話才算數？

我之前在整理 Company Brain 的架構時，把它拆成五個層次，包含捕捉脈絡、保留原因、追蹤承諾、保持最新，以及權限與治理。書裡講的全域感知、留住決策脈絡跟計算高管承諾的「言行一致指數」，把前面三層講得很透徹；但我們自己動手做記憶系統一路踩坑下來，發現最讓人頭痛的往往是後面兩層，尤其是「保持最新」。

舉個日常每天都在發生的場景，有人在 Slack 裡問了一句「客戶那邊還在卡，我們是不是把交期延到下週二？」，底下有人回個貼圖，過兩天業務又在另一場小會上口頭說「跟客戶喬好了，照原定時間上，但這次先拿掉兩個小功能」。這時候如果系統把所有對話、會議紀錄跟文件編輯軌跡全抓進來，它要怎麼分辨哪一句只是隨口提議、哪一句是已經解除的舊警報，哪一句才是最後拍板的正式承諾？

像書裡很喜歡拿「文件編輯軌跡」當例子，提到下屬寫的風險提示被直屬主管刪掉，系統就能抓出被隱瞞的風險。但在真實工作裡，也有可能是那個風險在下午另一場討論已經確認解掉了，或是下屬一開始搞錯了客戶規格，主管看過才順手刪掉。我們之前在測 Agent Memory 的可靠度（像 HaluMem 與 STALE 這類研究在解的問題）時就發現，模型很容易把「我猜、還沒確認」這類字眼吃掉，直接記成鐵錚錚的事實，或是當新狀態出現時忘記淘汰舊的前提。如果底層記憶沒有把「成立前提」跟「時效版本」管好，送到 CEO 桌上的那份底稿，很可能會混進一堆已經過期的誤會 🫠

而就算我們在工程上把記憶的時效與版本都解乾淨了，當這套能看穿所有細節的系統放進真實組織裡，緊接著還會碰上另一層人性上的考驗。

眼睛與監控器的邊界：怎麼讓大家敢在系統裡留真話？

書裡對人性的反應其實寫得非常誠實。作者在介紹完這套能讀取郵件、會議語氣跟修改軌跡的「老闆 AI」之後，自己補了一段很關鍵的提醒：「透明是用來照亮事的，不是用來嚇唬人的。」他也坦承這條邊界一旦守不住，老闆 AI 就會從一雙眼睛退化成一台監控器，而監控器治不了人心，只會讓想法藏得更深。

但要守住這條線其實沒那麼容易。書裡前面在批評傳統 KPI 的時候，才剛引用過古德哈特定律（Goodhart’s Law），也就是當一個指標變成考核目標，它就不再是個好指標。如果今天員工跟主管知道，自己在文件裡刪掉的每一句話、開會時的語氣，都會留在公司檔案裡，還會被拿去計算「言行一致指數」跟「跨部門意見被採納的頻率」來做年底的績效評估，大家下意識一定會先保護自己 😅 在公開信件跟會議上許承諾會變得越來越保守，真正有爭議、有風險、可能會得罪人的討論，最後還是會默默搬回電話、私人訊息或茶水間。

這也讓我們自己在設計 Cairn 與思考 Company Brain 的時候，更確定「記憶邊界（Memory Boundary）」必須在系統架構上就先切開，不能只靠老闆個人的自律來守。我們在〈當 Memory 也會被攻擊〉跟最近的架構設計裡，一直把「個人的工作草稿（Working Memory）」跟「公司的正式記憶（Company Brain）」分開處理。討論過程中那些還不成熟的點子、猶豫、抱怨跟試錯，應該留在個人或小團隊安全的草稿空間裡，不需要每一筆都被送到 CEO 眼前；等到討論收斂、真正拍板了，再由有權限的人把「正式決策、當時考量的原因、成立的前提，以及誰接下了哪個承諾」寫進公司的共同記憶裡。

從底層記憶做到組織大腦，剛好在半路撞見同一件事

回頭看這小半年的軌跡真的蠻奇妙的。我們從 6 月開始投入做 Agent Memory，一開始是從底層的記憶怎麼形成、怎麼更新、怎麼確保可靠度一路往上蓋；9 月讀到《AI 未來已來》的時候，看到書裡從組織頂端的「老闆 AI」與「企業決策中樞」往下拆，當時就覺得兩邊想解決的問題竟然在半路接上了。最近跟越來越多創業者聊起 Company Brain，昨天又跟朋友重新聊到這本書，才發現很多我們在工程與產品上反覆推敲的細節，書裡其實早就從 CEO 的視角給出了很棒的呼應。

這本書最難得的地方，就是作者自己真的在帶公司、也真的動手用 Agent 跑過一輪組織轉型，所以裡面談的「知識風險地圖」「決策複利」跟「眼睛與監控器的邊界」，全都是第一線實作過才會寫出來的體會 🙌 推薦有在思考企業 AI 轉型、或是對 Company Brain 有興趣的朋友可以找來翻翻，不曉得看過這本書、或最近也在公司裡推 AI 知識庫與 Agent 的朋友，對裡面哪一個觀點最有共鳴？歡迎在下面留言聊聊 XD
